
這是**計算依賴順序**，不是把形變位移隨便加到已經蒙皮的世界座標上。

還要防止同一個 shape key 被兩套系統同時控制：例如動畫曲線寫一次、runtime 修形器又寫一次。每個通道必須有明確負責者。

這件事需要依實際引擎接入。例如 Godot 的 `SkeletonModifier3D` 官方說明指出，其骨架修改在 `AnimationMixer` 播放處理之後執行；實作不能在最終骨架修改之前，就取走舊姿勢來判斷修形。:chatgpt-content-reference{index="2"}

### 第五步：才開始製作與接入走路、睡眠、施法

這時候新增的是動作與互動配置，不是重新設計角色。

例如走路要設定腳掌著地時窗；睡眠要有躺下、睡眠、起床及床面支撐；施法要有抬手、釋放事件、收招。握劍則沿用既有握持能力和武器掛點。

**不能用幾個關節來回轉動的測試，冒充已經完成走路或睡覺。** 關節掃描是結構測試，完整動作是另外一項驗收。

## 三、怎麼驗證？我會設六道關卡

### 先看總表

| 關卡 | 實際測什麼 | 通過證據 |
|---|---|---|
| **結構與匯出** | 骨架、權重、morph、座標、動畫是否正確保存 | 驗證報告＋新程序回讀 |
| **關節活動** | 中立、典型、極端姿勢及多關節組合 | 數值＋固定角度灰模 |
| **完整動作** | 走路、躺下／起床、施法及接觸 | 實際播放影片＋逐時點檢查 |
| **轉場與互動** | 動作混合、IK、武器、床面、暫停與拖曳時間 | runtime 測試及失敗位置 |
| **視覺品質** | 是否自然、有支撐、無明顯凹陷與穿插 | 遊戲鏡頭與近景審查 |
| **凍結後新增動作** | 不改角色基礎，接入未用於調模型的動作 | 不變資料證據＋新動作通過 |

### 1. 結構合格，不代表動作自然

格式層可以使用 Khronos 的 glTF Validator，檢查 GLB 結構、資料引用、動畫存取資料，以及非法數值等問題。**它能檢查格式與資料合法性，不能替你判定握劍自然不自然。**:chatgpt-content-reference{index="3"}

你原本 r010 的保存與回讀門檻應保留，但要保持原適用範圍。**1 µm 是特定回讀精度要求，不是整個角色所有美術問題的統一判準。**

新角色造型若有正式修訂，匯出比較應是「新版製作來源對新版 runtime」，不是要求新造型和舊 r010 永遠一模一樣。

### 2. 接觸條件必須跟動作狀態走

這點很重要，否則 AI 會為了測試數字把角色做歪。

握劍時，沿用你原來的固定指腹區與接觸門檻；**放開劍、張掌施法或睡覺時，不應強迫每根手指繼續靠近劍柄。**

走路要檢查的是腳掌在「應該踩住地面」時有沒有滑動；睡眠要檢查指定身體支撐區有沒有穿床或漂浮。各項測量、單位、時窗與門檻，必須在調模型之前寫進契約，不能測完才改成容易通過的數字。

### 3. 不只測單獨播放，還要測轉場

我會要求測試不同播放速度、不同更新步進，以及短、中、長的動作轉場。例如：

**0.5×／1×／1.5× 播放；30／60／120 fps 求值步進；100／200／400 ms 轉場。**

這些是建議的測試工況，不是承諾你的硬體可以跑到 120 fps。

還要測暫停、恢復、直接拖曳時間、循環接縫，以及反覆切換動作。不能只證明「從第一幀順播一次沒出問題」。

完整片段需要檢查整幀、半幀，並在高風險接觸區增加取樣；但報告只能聲稱**受測時間點通過**，不能把有限取樣寫成連續時間絕對無碰撞。

### 4. 必須量「現在真的變形後的位置」

不能從模型原始的靜態頂點資料讀出數值，就說遊戲內動畫已驗證。

例如，工作區若實際使用相容版本的 Three.js，可核對 `getVertexPosition()` 這類考慮目前 morph 與 skinning 狀態的接口，再轉換到正確測量座標。官方文件明確區分了這種當前動畫狀態的頂點位置。:chatgpt-content-reference{index="4"}

但這仍須搭配實際畫面；CPU 幾何取樣不能冒稱 GPU 畫面已檢查，更不能取代美術審查。

### 5. 刻意製造錯誤，確認檢查器真的會抓

我會要求 AI 在**可丟棄的測試副本**做反例：

移除必要修形或骨骼映射、把劍柄移入手內，或在已知需要修正的姿勢關閉修形。對應測試應該明確失敗。

**一個永遠顯示 PASS 的檢查器，對你沒有價值。**

## 四、最關鍵的驗證：凍結角色，再給它一個新動作

這才是回答你「是不是每次都要重新設計」的直接證據。

### 具體測法

假設 AI 已用走路、握劍與睡眠動作，把角色基礎調整完成。

此時凍結：

**網格、骨架休息姿勢、權重、通用 shape keys、驅動規則，以及共用 runtime 修形程式。**

接著加入一段**沒有拿來調整這個角色的施法動作**。

這一次允許新增動畫曲線、骨骼對應設定、技能事件和接觸時窗；但不允許為了施法再雕手臂、重畫權重，或加上「當動畫名稱等於某招，就特別推這個點」的程式。

如果正常通過，就有證據支持：

> **這個角色基礎可以重用，而不只是記住已經做過的幾段動畫。**

如果失敗，也不能暗改角色後說「新增動作不用改模型」。應承認 V1 的通用能力有缺口，修正後升版；原失敗動作轉為回歸測試，再加入另一個未用於調整的案例。

**雜湊也要比對正確的資料。** 新增動畫本來就可能改變整個 BLEND 或 GLB 檔案，所以不能只比整個容器的檔案雜湊；應分別核對網格、休息骨架、權重和通用修形等被凍結的內容。

這是我會寫進交付契約的核心，而不只是要求「多測幾個動作」。

## 五、怎麼給 AI 執行？

把上面的 **:chatgpt-content-reference{index="8"}[完整執行規格](sandbox:/mnt/data/character_animation_v1_codex_spec.md)** 拖進本機 Codex 對話，再貼下面這段。

完整規格已包含實作順序、驗收方法、失敗分類、候選預算與權限邊界；下面是啟動指令，不要求你逐項人工操作 Blender。

```text
請讀取附件 character_animation_v1_codex_spec.md，
在目前 mmo-asset-pipeline 工作區執行「可重用角色動畫 V1」。

目標：
不要繼續只改善一個右手握姿。
我要完整角色可以重用同一套模型、骨架、權重與通用修形，
支援走路、躺下／睡眠／起床、施法與必要轉場。
最後必須證明：角色基礎凍結後，接入未用於調模型的新動作，
不需要重新雕網格、畫權重或增加招式專用修形。

先執行，不要只回計畫：
1. 核對真正 worktree、最新任務、完整角色來源、r010 歷史，
   以及交付 runtime 的真實引擎與版本。
2. 讀實際存在的 art-engineer、character-artist、rigging
   和相關動畫／匯出／QA 技能，不把公開同名技能當成已安裝。
3. 沿用現有腳本、測試入口與資產流程，先完成一個實際的
   BLEND → GLB → runtime 載入、動畫、修形、渲染與量測閉環。
4. 再按附件契約修正角色基礎，建立依關節姿勢啟動的通用修形，
   分開處理身體變形與握柄等接觸修形。
5. 建立可以操作的動作測試場景，完成完整動作、接觸、
   轉場、播放速度、暫停／seek、反例及凍結後接入測試。

必須遵守：
- 使用真正完整角色，不能以假人或局部右手冒稱全身完成。
- 保存原始資產、r010 與後續歷史，不覆寫失敗。
- 不因新增動作，就建立動畫名稱或固定幀號的形變特判。
- 通用修形必須在目標 runtime 有正確、可驗證的實作；
  Blender 裡正常不等於遊戲內正常。
- 保留原握持驗收與接觸區，只在規定握持時窗要求接觸。
- 新驗收條件先定義，再製作；不能事後放寬換取 PASS。
- 按附件與工作區有效規則記錄預算，不改名延長候選。
- 依有效政策取得真正的獨立審查結果；
  路由成功不等於審查已執行。
- 同一 BLEND／場景只有一個 writer。

權限：
僅在既有授權工作區的副本內製作與測試。
不 stage、commit、push、merge、部署。
不新增付費生成，不安裝全域工具或外掛，
不修改 Blender 安裝檔、全域 Codex 設定或其他 repo。
需要改動受保護區／骨位／拓樸或擴張權限時，
先提出具體差異與理由，等待授權。

交付：
可編輯完整角色、runtime 資產、通用修形與接入資料、
可啟動的 QA 場景、實際重跑命令、影片／截圖、
數值與反例結果，以及凍結後新增動作的差異證據。

分開回報：
結構／匯出、runtime／轉場、美術、凍結後重用、效能，
以及原完整角色交付需求的狀態。
工具測試通過不能代替美術或遊戲驗收。

先完成附件 P0 和 P1 的實際工作；
來源、工具、授權與預算成立就持續推進。
只有真實阻礙、必要變更授權、預算到頂或最後美術確認時停下。
```

之後再把「新增動作」收斂成現有 `art-engineer` 技能的可重跑流程，而不是每次貼一篇長提示詞。技能可以包裝固定指令、參考和腳本；但是否有效，仍要用具體輸入、執行結果與驗收測試證明。:chatgpt-content-reference{index="5"}

**你這次最應該要求的成果，不是「又有幾百項測試通過」，而是：你親自切換走路、睡眠、施法，看見同一個角色正常運作；再加入一個新動作，角色基礎確實沒有被偷偷重做。**
