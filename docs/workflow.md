# 從構圖到可動作、可換裝的遊戲資產

本流程的目的：讓美術能探索設計，再以可追溯的交付規格接入 Unity。規格鎖定的是相容性與證據，不是唯一的外形。角色、服裝、武器、建築與景觀使用不同分支。

| 階段 | 美術／工程工作 | 產物及進入下一階段的條件 |
|---|---|---|
| 01 設計探索 | 文字構圖、世界觀、輪廓變體、色彩與材質語彙、遊戲鏡頭距離 | brief、輪廓候選；允許低成本 PREVIEW |
| 02 設計拆解 | 正／背／側一致性、尺寸、內部厚度、腰帶扣接、背武器留空、換裝分件線 | 設計師檢視三視圖與分件／干涉標註；AI 盲區明確記錄 |
| 03 素材策略 | 選既有基準、Blender 手工／程序模型或獲授權的 Hyper3D 候選；每部件分別選擇 | 來源與使用權、生成參數、模型實檔；不以生成縮圖宣稱 mesh 可用 |
| 04 Blender 微調 | 比例、剪影、拆件、朝向、尺度、裝備留空；保留 highpoly 與原始生成版 | 設計定稿版本；固定角度預覽並列出差距 |
| 05 重拓樸 | 身體、臉、肩肘膝髖的變形 edge flow；硬甲另件；靜態模型依用途減面 | 真實三角數與拓樸檢查；Quad 輸出仍需關節驗證 |
| 06 UV／材質 | UV0 表面、需要時 UV1 lightmap 或 detail；high→low 烘焙；材質家族與 mask 契約 | 貼圖、材質配方、shader profile；重拓樸後重烘焙，不能沿用錯誤對應 |
| 07A 角色／服裝 | 骨架家族、版本化 bind pose、skin／rigid／secondary、權重修正、部位遮蔽 | 骨架和部件 hash、權重檢查、極限姿勢及換裝矩陣 |
| 07B 武器 | 握點、左右手 socket、背／腰收納、tip／trail 參考、剛體動畫 | socket／pivot 契約；武器尺寸不修改程式命中規則 |
| 07C 建築／景觀 | 可拼裝的底層模組、英雄破形、點綴件、頂點色／貼花、LOD、碰撞 | 拼裝樣板、玩家視角／路徑檢視與幾何／效能資料 |
| 08 匯出／Unity | FBX、材質映射、Avatar、Animator、SkinnedMeshRenderer 共骨架、LODGroup、collider | 已存在的匯出檔、Unity prefab 和匯入證據 |
| 09 驗收／交付 | 動作／換裝、視覺、效能、授權與版本追溯分開檢查 | production 交付包；任何缺證據標為 UNVERIFIED |

「重購」暫依本次上下文理解為重拓樸／重構；不是新增採購或購買服務授權。引擎版本、URP/HDRP、硬體與同屏角色數尚未指定，起始 budgets 不代表已證明的效能上限。

第一版僅已實作離線 brief／planner、固定來源整合與 Blender 技術檢查。上表的生成、蒙皮、烘焙、Unity runtime 與發布是製作工作流，不能從 planner 產生成功狀態推定完成。

## 試產里程碑

1. **可重用人形試件**：基準體＋兩套不同輪廓服裝＋武器，共用 6 種動作。量測肩／髖／裙襬穿模及換裝成本。
2. **美術特例試件**：巨漢或精靈體型、硬肩甲、長袍、特殊材質，建立新 rig/body/shader variant，測試哪些素材可重用。
3. **場景試件**：小城鎮模組、英雄地標、招牌／碎石／藤蔓／布幔；固定玩家路徑與視角檢查接縫、重複和效能。

先完成一個可玩的試件，測量修正時間與失敗原因，再擴大量產。使用者提出的 40% 排錯時間改善與 80% 穿模降低是未驗證假設，需相同任務基線、工時紀錄與缺陷數據。
